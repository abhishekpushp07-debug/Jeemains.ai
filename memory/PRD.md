## Owner (27 Nov): "website pe sign up = app pe login, aur ulta bhi? ek hi user list?" — CHECKED, already true, no code
- The app has NO account system of its own. App sign-up `POST /api/jl/auth/phone/signup`, sign-in `/auth/phone`, PIN change `/auth/pin`, forgot PIN, session, refresh, logout all go through `backend/jl_proxy.py` to `JEELIVE_API` (= jeelive.ai/api), the website's own backend. So an account made in the app is a website account (sign in on jeelive.ai with the same phone + PIN), and a website account signs in to the app. One user list = the website's. The app server keeps only app data (Rapid Fire profile, coins, Dream, Mission) keyed by the website's `uid`, read from the website's `/auth/me` (`rf_access.py`). The browser Rapid Fire (`/api/arena`) uses the same sign-in.
- Not automatic: being signed in on one device/browser does not sign another in (type phone + PIN once). Website → browser Rapid Fire without retyping (SSO ticket, `WEBSITE_NOTE.md` Phase 2) is NOT built. The website has no account-delete call (owner deletes the website account by hand, `account_deletion.py`).

- Frontend: Expo Router, Figtree fonts and Material Design icons.
- Native: talks directly to `https://jeelive.ai/api` using a cookie session (`EXPO_PUBLIC_JEELIVE_API`).
