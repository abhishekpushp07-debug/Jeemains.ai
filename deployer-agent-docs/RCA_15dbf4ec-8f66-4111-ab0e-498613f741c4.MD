## 4. Did Library delete touch Supabase? — NO
Confirmed from production source (`backend/tejas/library.py`):
```
async def drop_source(name, key, sid):
    """An upload's records leave the database. The platform file store keeps the original file bytes (it has no delete)."""
    if name == 'tejas_books':
        for part in BOOK_PARTS: await db[part].delete_many({'book_id': sid})
        await db.tejas_jobs.delete_many({'set_id': sid, 'kind': 'book_step', 'status': {'$ne': 'running'}})
    await db[name].delete_one({key: sid})
```
- `drop_source` only deletes **Mongo** records. There is **no storage/Supabase delete** anywhere in `library.py` or `tejas_storage.py` (`tejas_storage.py` has no delete function; the only `.remove()` is on a local in-memory `_source_cache` list). The single DELETE-to-storage in the repo is in a **test** file (`tests/storage_real_qa216.py`), not runtime code.
- No Supabase DELETE appears in logs (note: backend access logs are inbound-only; the authoritative evidence is the code path above).
- Corroboration: the owner deleted the chemistry upload at 17:38 (audit "0 tests, 1 uploads", resource `eed94a04…`), then **re-uploaded the identical file at 17:45** (same sha256-derived id `eed94a04…`) which completed 200 — proving the storage path is intact.

**Conclusion:** Deleting from the Library removed only database records. Your Supabase original PDF bytes were not deleted.
