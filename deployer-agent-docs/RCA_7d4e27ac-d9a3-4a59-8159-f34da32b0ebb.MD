## ROOT CAUSE — the page reader never classified any Answer-key or Solution page
Page classification (collection `tejas_book_pages`, 640 docs) distinct values = `[cover, contents, instructions, questions, unresolved]`. Counts:
- **questions: 183**
- instructions: 20
- cover 1, contents 1
- **unresolved: 435**
- **answer_key / solutions: 0  ← ZERO pages classified as answer key or worked solution anywhere in the 640-page book**

`tejas_question_solutions` = 0 docs. No worked solution was captured for any question.

Page-by-page sample (sorted) confirms the pattern: p1 cover, p2 contents, **p3-6 questions (Ch1 questions)**, **p7-17 `unresolved`** (these are exactly Ch1's Answer key p7 + Solutions p7+ per the bookmarks), p18 instructions, p19-21 questions (next chapter), p22-25 questions, …

### Why
In `backend/tejas/book_reader.py::read_page`, a page only becomes `solutions`/`answer_key` when:
- a left-margin running section header matches the `ROLE` regex → sets context role to `solution`/`key` (`scan_headers`), and/or
- `key_cells(body)` finds a printed answer-key table, and/or
- per-item solution anchors match the running number `in_sequence`, and/or
- an `open_s` worked-solution continuation carries over.

For this PDF none of those fired on the Answer-key/Solutions pages, so they hit the fallback branch `if not anchors and not shared:` → classification `'unresolved'` with the issue **"No reliable question or key anchors; classify or attach this continuation."** Because no page is tagged `solution`/`key`, the publish/rebuild step (`book_publish.py`) maps only the question pages into each mock:
- Every chapter mock has `pages.key = []` and `pages.solution = []` (only `pages.question` populated).
- Every question gets `solution_kind: "answer_key_only"`, `answer: ""`, and `solution: "Supplied answer key: . This book does not contain a worked solution."`

This is a deterministic limitation/bug in the native page reader's solution/answer-key detection for this book's layout (per-chapter "Questions → Answer key → Solutions"). It is NOT an LLM/vision failure (no AI calls were made, none logged), NOT a secret/config/infra issue, and NOT a stalled worker.
