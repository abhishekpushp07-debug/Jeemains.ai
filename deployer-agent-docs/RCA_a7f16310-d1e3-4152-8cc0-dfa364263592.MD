# RCA — Android APK/AAB download shows "Nothing is connected" (jeelive-mobile)

## Symptom
User published Android build; clicking **Download** for both the **APK** and the **AAB** shows (Hindi→EN) "Nothing is connected to it". No file downloads, app never installed. This is a download/artifact problem, not an in-app/runtime error. Production backend is confirmed healthy and is NOT the cause.

## What the pipeline actually did (verified from logs)
Two Android store runs were created for this publish (one per artifact):
- **APK run** `dbuklsa4hkhs739fpgsg` → CodeBuild `9dbef7f9…` → EAS build id **8f1e9836-8af9-479b-851d-5dd5b7e80f70** (profile `apk`, EAS env **preview**, versionCode 137→138).
- **AAB run** `dbuklsa4hkhs739fpgu0` → CodeBuild `b018fd69…` → EAS build id **3307641d-1cb4-4506-82a9-17a44a5fd227** (profile `app-bundle`, EAS env **production**, versionCode 138→139).

Both CodeBuild steps (`android_prepare`, `android_eas`) are **success**, but that only means **submission** succeeded. The submit command is:
`eas build --platform android --profile <apk|app-bundle> --non-interactive --no-wait --clear-cache --json`
Because of `--no-wait`, CodeBuild exits green the moment the job is queued on Expo. The **actual native Gradle build runs afterward on Expo's servers**, and the finished build + downloadable artifact URL are delivered back only via the webhook `https://api.emergent.sh/api/v0/android/webhooks/eas` (registration confirmed "already registered").

## Root cause
**"Nothing is connected" = no artifact URL is attached to the build record** → the EAS native build never delivered a finished, downloadable APK/AAB through the webhook. The green CodeBuild status is submission-only and does NOT mean the APK/AAB was produced. Because it affects **both** artifacts identically, the failure is in the shared native-build config, not one profile.

I could NOT read the EAS native build logs directly — they live on expo.dev (`https://expo.dev/accounts/emergent-em-user-79a301ca-f641-4cbc-8eb1-b53902eb5413/projects/jeelive-mobile/builds/<id>`), outside the deployer's log tools, and a native Android (Gradle/Android SDK) build cannot be reproduced in the eph sandbox. So the EAS-side outcome (failed vs still-queued) is **diagnosed, not verified**.

## Most likely trigger (config-level, unverified on EAS)
`frontend/app.config.js` still exists at native-build time and, by Expo config precedence, **overrides the pipeline-normalized `app.json`**. It force-enables R8 code minification + resource shrinking on EVERY release build via `expo-build-properties`:
```js
return [name, { android: {
  enableMinifyInReleaseBuilds: true,
  enableShrinkResourcesInReleaseBuilds: true,
  enableBundleCompression: true,
  useLegacyPackaging: arm64,
  ...(arm64 ? { buildArchs: ["arm64-v8a"] } : {}),
} }];
```
R8 minify + `shrinkResources` on a release build of this dependency set (react-native-reanimated 4 + react-native-worklets, react-native-webview, react-native-share, vector-icons, view-shot, etc.) is a classic cause of a **failed release Gradle build with no artifact** — and it applies to both apk and app-bundle profiles, matching "both downloads empty".

Secondary observations (not download-blocking, worth noting):
- The two profiles resolve **different EAS environments** (apk→preview, app-bundle→production); both reported "No environment variables found", so `EXPO_PUBLIC_BACKEND_URL` referenced in `app.config.js extra.backendUrl` is undefined on EAS at config eval. Runtime concern only.
- `app.json` slug is `frontend` but is force-set to the app slug by the pipeline; project is correctly linked to Expo project `f13b328b-ba41-499f-ac19-15e70feb69f0`.

## Suggested fix / next steps
1. **User (first, fastest):** Open the two EAS build pages above and read the native build status/logs. If they show **errored** → it's a build failure (go to step 2). If **in-queue/in-progress** → pooled-account queue; wait and re-check, the download appears once EAS finishes. Then re-press "Generate build" from the Deployment panel (agent cannot trigger store builds).
2. **Source (if EAS logs show a Gradle/R8 failure):** In `frontend/app.config.js`, disable the aggressive release optimizations to get a buildable artifact:
   - set `enableMinifyInReleaseBuilds: false` and `enableShrinkResourcesInReleaseBuilds: false` (keep `enableBundleCompression` optional). Re-generate the build. If a later build must re-enable minify, add proper ProGuard/R8 keep rules first.
   - NOTE: this is a candidate fix — it was NOT verified in-sandbox because native Android builds require the Android SDK/Gradle and cannot run in the eph pod. Confirm against the EAS build log before shipping.
