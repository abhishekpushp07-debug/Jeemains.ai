## Root cause (why every mock is held with 25000 blocking issues)
The book was ingested as 4481 **native** pages (scanned_pages=0, nothing OCR/region-scanned,
manually_repaired_pages=0, ai_proposed_pages=0). The mock-assembly/classifier then produced
mocks that have **no validated answer keys**:
- All 50 mocks have `pages.key = []` (zero answer-key pages mapped) and 47/50 have
  `pages.solution = []`.
- Answer-key pages are being mis-classified: page 2251 is literally an "Answer key" page, yet
  its `classification="instructions"` and its only region is `role="instructions"` (not
  `role="key"`). So the key never attaches to the mock.
- All 50 mocks also have `rules = {}` (no scoring/section rules set).

Because keys/solutions are never bound and no region is `checked`, the builder emits a
per-question review warning for essentially every question region on every page — the four
dominant templates ("Leading content…", "confirm response type…", "Answer visible near Q#…",
"crop boundary crosses…") alone each span 2.9k–4.4k pages — totalling the app-reported
`blocking_issues = 25000`, and every mock lands in `state="held"`.

This is driven by the app's PDF-ingest region-role / classification logic (answer-key &
solution pages tagged as "instructions"), compounded by this being an un-scanned, un-reviewed
native import with no rules. It is NOT a deployment, build, secret, tier or infra problem —
the deployment is live and serving.

## Suggested fixes
1. CODE (E1): Fix the ingest classifier/region-role assignment so "Answer key" / "Solutions"
   pages are tagged role="key"/"solution" and bound into `mock.pages.key` / `mock.pages.solution`
   (currently key=[] for all 50 mocks). With keys bound, the per-question "source region needs
   review" / "confirm response type" warnings should auto-clear instead of accumulating to 25000.
   Reproduce against a single mock-book PDF in /super-admin/upload.
2. USER: For this already-imported book, the expected recovery path is the Attention Needed
   queue / review-desk scan+repair (pages are native & scanned:false, manually_repaired=0) and
   setting mock rules (rules={} on all 50). Given keys weren't detected at all, pursue fix #1
   first; otherwise the owner faces 25000 manual region confirmations.
