# Authentication testing contract
Use /app/memory/test_credentials.md, never log secrets. This app uses custom owner/reviewer password login and explicitly unverified phone-only student entry; do not implement new auth or treat a phone as verified ownership.

## Current production login/slow-loading investigation
- User reports deployed site slow then login error. Reproduce exact production URL/error and inspect deployment logs/env routing before modifying code. Current preview login navigation ~287ms, session GET ~156ms, Mongo ping5ms; no cause confirmed yet.
- NEVER write test users, sessions, attempts or rate-limit records into the customer database. Run login success/refresh/logout/role tests in the existing isolated ASGI database with copied minimal credential state or synthetic test credentials; no real-owner login attempts. Production diagnosis is read-only unless explicitly authorised.
- Verify bcrypt hash shape and unique normalized email, staff credential-generation fencing, student-only phone profile plane, JWT/session expiry and HttpOnly Secure SameSite cookies, session ownership, logout revocation and throttling. No secrets in reports.
- Test actual /api/auth/login, /api/auth/phone, /api/auth/session, /me, /refresh and /logout contracts. Registration is disabled410; no open staff registration or OAuth bypass. Invalid credential/type errors must display as text, never crash JSX.
- Origin regression matrix: configured FRONTEND_URL plus explicit comma-separated CORS_ORIGINS must be the single normalized set used by CORS and unsafe-write fence. Legacy literal wildcard is ignored with a warning and never trusted. Invalid explicit configuration fails closed. Test canonical/additional hosts, duplicate/whitespace/trailing-slash/default-port configuration, hostile suffixes/substrings, null, missing Origin, wildcard/path/userinfo/query/fragment/control characters, and identical CORS/fence decisions. Never reflect request Host/forwarded-host into trust.
- Origins must be explicit and correct for deployed frontend/API. Cross-origin writes from unrelated origins remain denied. Verify Origin, CORS headers, frontend built API URL, forwarded host/protocol and cookie retention across session bootstrap and refresh. Do not replace them with wildcards or disable secure-cookie/CSRF checks.
- Measure browser document/JS/API timings and login request status separately; do not claim a performance fix from a preview-only timing. User A must not read B attempts, sources, crops or reports.
- No credential rotation, owner-email migration, production secret edits or customer-data resets without explicit authorisation. Verify deployment status and DB binding before any redeploy.
